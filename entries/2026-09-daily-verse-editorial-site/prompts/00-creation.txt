从零构建一个对外演示级网站「一日一诗 · Daily Verse」:AI 诗词品读站,每天一首真实诗词,AI 带你读。

核心体验(零输入,首屏即诗):
- 访客打开页面,立即看到今日诗签(一首真实诗词的全文、朝代、作者)与 AI 品读的流式生成;非触发访客看到当天已生成的完整品读。
- 所有访客共享同一首「今日之诗」——这是演示点。

视觉规格(编辑/出版美学,严格执行,不要深色电子风):
- 底色宣纸暖白(#f7f3ea 系),文字墨色(#2b2b2f 系),点缀朱砂(#c93b2e)。
- 衬线字体优先(Noto Serif SC / Songti SC / serif);诗题可竖排(writing-mode: vertical-rl);纸纹质感(纯 CSS 实现,不用图片);印章式朱砂徽章;细墨线分隔;大量留白。
- 禁止:深色背景、霓虹色、辉光、雷达/网格图案。
- 1440×900 / 390×844 / 327×603 无横向溢出;触控目标 ≥44px;支持 reduced-motion。

数据与后端(使用 Enter Cloud):
1. 数据源:今日诗词公开 API(https://v1.jinrishici.com/all.json,免 key,服务端抓取)为主;内置 30 首公共领域诗词(全唐诗/宋词)作为降级后备——API 不可达/超时(独立 try/catch)时自动选用后备并诚实标注来源(「诗源:今日诗词 API」或「诗源:馆藏诗选(外部 API 暂不可用)」)。后备诗选避免连续两天同一首(按 day 取模选)。
2. 按天幂等惰性刷新(不做 cron):任何访客加载页面时,边缘函数检查当天(UTC+8)是否已有诗签;无则抓取诗源 → 调用 AI 流式生成品读 → 持久化;有则直接返回。day_key(当天日期字符串)唯一约束保证一天只生成一首,并发重复插入被唯一约束兜底。
3. 表:verse_snapshots(id, created_at, day_key text unique, title, author, dynasty, lines text[], narrative, source)。RLS 开启:public read,写入仅 service role。
4. AI(Poetry Reader 人设):基于诗文生成三段式中文品读——白话译意(忠实)、意象赏析(只基于诗文中的意象,不编造历史背景)、今日一读(一句当下联想,明确标注为主观随想)。禁止虚构:不知道的背景就不说,宁可少写。

页面结构:
- 诗签 Hero:今日日期(农历风格或公历)、诗题(竖排)、朝代·作者、诗文(逐句,衬线大字)。
- AI 品读区:流式渲染三段品读(Markdown 安全渲染,不渲染原始 HTML);诗源标注。
- 复制诗签按钮:一键复制今日诗签的 Markdown 文本(诗题/作者/诗文/一句品读摘录),复制成功有短暂反馈,失败降级不报错。
- 往日诗签:历史诗签时间线(日期+诗题),点击可查看对应诗文与品读,可返回今日。
- 页脚:一句话说明「诗源:今日诗词 API · AI 品读每日一生成 · 所有访客共享同一首」。

约束:
- AI API key 只在服务端边缘函数;客户端无任何密钥。
- 抓取/生成失败有可见降级(展示最近成功诗签 + 提示),不白屏、不往 console 打 error。
- 不发布、不公开分享、不生成图片素材。
- console 0 error。

完成后回复:实际修改文件、边缘函数与表结构、AI 配置、降级路径说明、执行的检查及结果、预览已更新的明确状态。
