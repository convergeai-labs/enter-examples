- 当前预览: https://d41c8754b3a14836980c67b0acfcddfa.live-preview.enterapp.pro/

背景:目前 PULSE Observer 是单次 LLM 调用。本批次让它成为真正的工具使用 Agent:自主决定深潜哪些条目 → 调用工具抓取详情 → 基于真实抓到的内容写深度解读。

本批次新增内容(一个内聚批次):
1. 工具化深潜循环(全部在边缘函数内,有界):
   a. 选择阶段:快照生成时,主解读流完成后,独立 Gemini 调用接收本轮全部条目清单(来源/排名/标题/热度),自主选出最多 3 条「最值得深潜」的条目,返回严格 JSON 数组 [{source, hn_id, reason}](reason 为一句中文选择理由)。解析失败/超时 → 本快照无深潜,静默降级,不影响其他内容。
   b. 工具执行阶段:服务端按选择结果抓取真实内容(这就是 Agent 的工具):HN/Lobste.rs 条目用 https://hn.algolia.com/api/v1/items/{hn_id} 取正文与前 3 条顶级评论文本;GitHub 条目用 https://api.github.com/repos/{full_name}/readme (Accept: application/vnd.github.raw) 取 README 前 2000 字符。每个工具调用独立 try/catch + 合理超时,失败则该条目跳过并在 UI 注明。
   c. 深潜写作阶段:再一次独立 Gemini 调用,输入为选择理由 + 真实抓到的正文/评论/README 摘录,为每条输出 2-4 句中文深潜解读(这东西实际是什么、社区怎么看、为什么值得关注)。严格约束:只基于抓取到的真实内容,禁止虚构;抓到什么写什么,内容少就写少。
2. 存储:pulse_items 新增列 deep_dive text null、deep_dive_reason text null(迁移向后兼容,旧行为 null 前端不显示)。
3. 前端:实时解读面板与热榜信号之间新增「Observer 深潜」区——展示本轮 Agent 自主选择的条目(最多 3 条),每条包含:原标题与来源徽章、选择理由(reason)、深潜解读(deep_dive)、工具来源标注(如「内容来自 HN 评论抓取」/「内容来自 GitHub README」);某条工具抓取失败时显示诚实提示。历史快照查看时同样展示(老快照无数据则不显示该区)。该区的设计目标是让观众清楚看到 Agent 的「选择→调用工具→解读」全过程。
4. 成本与有界性:每次快照生成最多增加 2 次 LLM 调用(选择 + 深潜)与最多 3 次工具抓取,全部在既有 15 分钟全局锁约束内;任何一步失败只影响深潜区,主解读/点评/动量/周报全部不受影响。

行为不变量(不得回退):
- 15 分钟惰性刷新锁、周报周锁、三源雷达、条目点评、排名动量、跨源共振、周报区、历史切换全部保持。
- RLS 语义不变:public read / service-role write;新列同样 public read;密钥只在服务端;客户端零密钥。
- 禁止虚构:深潜内容只基于真实抓取;选择理由由 LLM 生成但必须对应真实存在的条目。
- Markdown 安全渲染;深潜文本按纯文本/安全 Markdown 渲染,不渲染原始 HTML。
- 1440×900 / 390×844 / 327×603 横向溢出 0;触控目标 ≥44px;console 0 error / 0 unexpected warning。
- 迁移向后兼容:旧快照(无 deep_dive 列数据)正常渲染。
